# v0.2.1 — Antigravity ACP primary loops, accounts & quota views, and panel improvements

These are preparation notes for v0.2.1, not evidence that release archives or a Homebrew update have been published. They summarize the changes selected for this release since v0.2.0. The full entry-by-entry list is in the [changelog](../../CHANGELOG.md).

## What is new

**Antigravity standalone ACP adapter and model-free `/usage` quota.**
- **Standalone primary-only `adapter: antigravity`** (`agy acp --stdio`) registered in configuration, JSON schema, adapter factory, `doctor`, and `looptender init --agent antigravity`. Uses an owned detached ACP worker with create-once prompt reservations, exact `session/resume`, owned stop (`stop -immediately`), per-message streaming bounds, process-group/job termination, 64 KiB stderr capture, turn-directory pruning, and unknown-only failures.
- **`looptender session clear-unconfirmed`** exposes explicit operator recovery when a supervisor crash leaves an unconfirmed Antigravity turn (`acp-pending.json` without `acp-started.json` or `acp-not-started.json`), preserving any saved session and active holds.
- **Model-free Antigravity `/usage` quota** in `looptender accounts usage`, the Accounts panel, and the native menu for selected inherited `agy` accounts (`source: "agy:/usage"`, `freshness: "provider_unknown"`).
- Fallbacks, switch-back, separate account directories, per-loop model flags, and IDE-chat attachment remain unavailable for Antigravity (`fallbacks add` and `init --fallback` refuse cleanly).

**Accounts, quota summaries, and route management.**
- Named account connections and person-started **Connect Claude** / **Connect Codex** actions in the Accounts panel.
- Explicit selected-context subscription-quota reads (`accounts usage`) and compact saved quota summaries shared between Accounts and the native menu, with separate Codex/Claude/Antigravity buckets and explicit freshness/missing-value labels.
- Guided route configuration in the panel (add, reorder, enable/disable, and review-before-apply with `--allow-changes`) plus `--loop NAME` across `fallbacks` subcommands and `--account ID` in `init` and `fallbacks add`.
- **Usage** page in the panel summarizing 7-day savings, withheld wakes, send counts, and context-window readings.

**Supervision, transfer, and assignments.**
- Opt-in `loop.prompt_context` (default off) to append supervision context to wakes, nudges, re-prompts, and briefs with recorded byte counts and provenance.
- `looptender transfer inventory` (read-only BB thread and git worktree inventory) and `transfer preview` workspace/relabel checks.
- Explicit BB assignment lifecycle (`assignment inventory|review|handoff|acknowledge|ready|reconcile-wake|show`) and whole-objective completion review (`complete --review-file`).
- Hardened PR-backlog safeguard, stopped-turn publication, and scheduler/panel accessibility improvements.

## Upgrading

1. Once release artifacts and the Homebrew tap are published, follow the [upgrade and restart guidance](../setup.md) and [service instructions](../services.md). Replacing an executable does not upgrade an already running supervisor.
2. Existing v0.2.0 configurations continue to validate without changes.
3. For Antigravity loops, ensure `agy` is installed and signed in, then run `looptender init --agent antigravity` and `looptender doctor -c <config>`.

## What is fixture-tested and what is live

**Live, with what was observed:**
- **Antigravity (`agy 1.5.13`, macOS arm64, 2026-11-19/20):** verified `agy --version`, `agy acp --stdio` `initialize` (`sessionCapabilities.resume: {}`), model-free `/usage` quota retrieval via `looptender accounts add`/`usage` (all 4 Gemini / Claude-GPT windows), `looptender init --non-interactive --agent antigravity`, `looptender doctor -c <config>`, `looptender enable -c <config>`, two-turn `looptender tick -c <config>` with exact `acp-session.json` `session/resume`, and `looptender stop -c <config> -immediately` stopping an active turn cleanly.
- **Open live checks for Antigravity:** live tool-permission hold (`AwaitingUser` + `looptender resume`) and Linux/Windows installed walkthroughs remain open; chat-only questions without ACP elicitation remain indistinguishable from `end_turn`.

**Fixture-tested only, not observed live:**
- Antigravity permission-hold checkpointing, `CancelTimeout`, `WriteTimeout`, process-group/job termination, `ClearUnconfirmed` (`looptender session clear-unconfirmed`), and conformance suite.
- Panel route/account-connect controls, `loop.prompt_context`, `transfer inventory`, and assignment lifecycle commands.
