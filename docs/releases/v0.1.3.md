# v0.1.3 — Reliability and incident diagnostics

This release adds persistent work limits and keepgoing-owned evidence for understanding why a loop stopped. The supervisor still acts only on structured signals. It does not interpret transcripts, run review panels, or manage repository changes.

## Changes since v0.1.2

- `keepgoing timeline` combines bounded incident history, notification delivery evidence and current control flags in an offline text/JSON view. It shows observed errors, hold decisions, continued checks, failed alerts and evidence gaps without querying providers or modifying state. Use `--state-dir` for copied records or a broken config.
- Ticks record normalized observations, structured provider codes/statuses, ordered decision inputs and control snapshots. Control commands record saved flag changes without private notes or owner IDs. History is bounded and local; unavailable source timestamps remain unavailable.
- Status and doctor retain failed or unconfirmed notification warnings even while the loop is held. Recorded HTTP acceptance does not establish receiver or human receipt. Reading diagnostics never retries a report or clears a hold.
- Active BB provider retries no longer consume ordinary stall nudges or cause false nudge-cap holds. Verified recovery restores ordinary stall handling without resetting spent allowances or existing holds. Missing or incomplete structured evidence remains conservative.
- Optional `loop.limits.deadline`, `max_sends`, and `no_progress_timeout` bound future automatic work. Guided setup exposes matching flags. Send reservations and Git-progress timing persist across turns and restarts; `resume` does not replenish them. These controls do not measure spend or useful work, and a deadline does not cancel an already running turn.
- A subscribed `complete` event reports a new completion declaration once. The saved completion flag prevents command/restart replay; delivery uses one attempt without redirects. A declaration is not independent proof of success, and interrupted or rejected delivery can be lost.
- Git-progress inspection treats inaccessible tracked-file metadata as unknown rather than a deletion. Setup now describes `--wake-every` as stall-nudge spacing; idle wakes follow the check cadence.

## Verification and limits

Native macOS/Linux CI runs setup and recovery smoke checks against built binaries. The recovery fixtures cover BB, process, Claude and Codex stand-ins, rejected local alerts, held daemon restarts, explicit recovery, headless session reuse, owner protection and completion without replay. Release publication also requires archive checksum checks and both smoke scripts against the unpacked Linux executable.

This evidence uses synthetic events and local processes. It does not certify real network outages, live headless multi-turn compatibility, cancellation, installed-service lifecycle, a fresh five-minute onboarding experience or readiness to migrate other BB threads. Windows diagnostics and cross-build checks are separate from native recovery acceptance. No real outage or quota exhaustion was manufactured.

Goal records, multi-model triage, the optional menu-bar view, BB target transfer, and native Cursor/Antigravity chat adapters are not delivered by this release. Keepgoing remains the supervisor; users do not need a separate loop skill.

## Upgrade notes

- New diagnostic and limit features require this release or a development build containing them; v0.1.2 remains sufficient for basic guided setup.
- Replacing a binary does not update an already running daemon. Record the old executable version and private state location, stop only the identified supervisor process, install the verified artifact, and restart it with the same configuration. Preserve control flags, ownership, session metadata and accounting files. Do not use `resume` as an upgrade step: it clears holds.
- Existing config files remain valid; new work limits are opt-in. Enabling a send limit on an existing loop does not retroactively count sends made while accounting was disabled. Review the [limit semantics](https://github.com/connorburgess/keepgoing-agents/blob/v0.1.3/docs/operations.md#total-send-allowance) before enabling them.
- Legacy incident records upgrade on append without inventing historical fields. History remains bounded, and recording failures remain explicit. There is no guarantee that older binaries can read newer diagnostic schemas; retain a private backup before any rollback.
- The BB plugin is distributed separately from the CLI archive and Homebrew formula. Installing the CLI does not replace a timer, transfer a thread, change a login, or enable fallbacks.
