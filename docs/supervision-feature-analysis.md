# Supervision feature analysis

Reviewed 2026-11-12 against keepgoing main at `91f42dd` and BB 0.48.1's locally installed guides. This is a documented-capability comparison, not a live comparative benchmark. Vendor behavior and availability can change; recheck the cited sources before implementing an integration. Local BB guide evidence can be reproduced with the commands listed below; no account, prompt, runtime-state or private path is needed.

Current-goal prompt transport is being implemented separately in [PR #89](https://github.com/connorburgess/keepgoing-agents/pull/89); this analysis does not count it as released or live-verified.

The aim is useful, testable improvements, not blanket feature parity. Keepgoing owns whether an existing loop continues, waits, stops or uses an authorized fallback. The agent host owns tools, chat, editor and turn execution. A timer may invoke keepgoing without making supervision decisions. Provider-internal retries must be observed to avoid duplicate work. Keepgoing must not spawn/re-parent threads, interpret transcripts as status, or become a general planner.

## Installation and model connections

The current Homebrew → init → doctor → start path is a useful CLI foundation. It is not yet the intended first-run experience. The proposed experience is install → select a detected supported host/account → define a goal and bounds → review → start. Optional menu visibility is a separate choice. The existing provider remains responsible for credentials and model execution; keepgoing must not invent a universal login or silently migrate an account.

Model freshness needs three separate concepts: an exact model ID, a provider-managed alias, and an unspecified provider default. Claude documents both aliases and exact names, with defaults and restrictions resolved by its runtime. A configured string alone is not proof of an immutable model version. [Claude model configuration](https://code.claude.com/docs/en/model-config) xAI publishes model and retirement information, but that API catalogue does not establish which models a Grok Bot subscription or a local CLI can use. [xAI models](https://docs.x.ai/developers/models)

Handle capability refresh in ordinary setup/doctor/check paths using bounded caches and structured provider interfaces where available. Catalogue refresh, changing a selected model, upgrading a provider CLI, and upgrading keepgoing are separate operations. No additional watcher is proposed. A failed catalogue refresh must not turn a previously selected model into an invented retirement. Provider-managed alias changes should be reported when observable; absence of resolved identity stays unknown.

## Deliberately defer

Do not rebuild an editor, chat platform, credential vault, cloud computer fleet, browser automation engine or model host for feature parity. Do not copy agent-created schedules or subagents into the supervisor. Do not auto-accept model verdicts, widen scope on agreement, silently update pinned models, or equate a successful webhook response with completed work. Multi-model review remains an external, bounded workflow, as section 9 specifies.
